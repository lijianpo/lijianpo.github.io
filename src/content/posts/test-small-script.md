有些工作每次只花几分钟，却会不断打断思路。比如从一份待办清单里找出没有完成的事项，再整理成可以贴进笔记的文字。

这篇文章使用一组虚构的任务，演示一个足够小的脚本。

## 先确定输入和输出

输入是带有标题和完成状态的任务列表，输出是未完成任务的 Markdown 清单。暂时不考虑界面、提醒和数据同步，把这一条路径走通就够了。

```javascript
const tasks = [
  { title: '整理阅读笔记', done: true },
  { title: '补充文章摘要', done: false },
  { title: '检查手机端排版', done: false },
];

const pendingTasks = tasks
  .filter((task) => !task.done)
  .map((task) => `- [ ] ${task.title}`)
  .join('\n');

console.log(pendingTasks || '所有任务都已完成。');
```

运行这段示例，会得到两条尚未完成的任务。原来的清单仍然保留，输出可以直接用于下一次整理。

## 给小工具一个明确的边界

写完第一版以后，可以依次检查三个情况：

1. 清单为空时，是否有清楚的提示。
2. 全部任务完成时，是否仍能正常输出。
3. 标题包含中文或空格时，是否保持原来的文字。

这些问题比“要不要加一个设置页面”更接近当前需求。只有真正重复使用之后，才知道哪些功能值得继续补上。

## 把使用方式也留下来

一个脚本的说明可以很短：输入放在哪里，怎样运行，输出是什么。如果一个月之后再次打开，还能立刻用起来，它就已经帮上忙了。

更长的过程可以留给[项目说明文档](/posts/test-project-readme/)。脚本本身则继续保持小巧，让下一次修改也足够轻松。
